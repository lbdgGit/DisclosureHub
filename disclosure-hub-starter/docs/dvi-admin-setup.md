# LBDG DVI editor — safe activation

The private administration page is `/admin` on the existing Next.js site. **It is intentionally disabled until its environment secrets are configured**. No secrets are hardcoded in this repository.

## One-time Vercel configuration

In the Vercel project **disclosure-hub**, go to **Settings → Environment Variables**. Add:

| Name | Value | Purpose |
|---|---|---|
| `LBDG_ADMIN_PASSWORD` | A unique, long admin password, preferably generated by a password manager | Required to sign in to `/admin` |
| `LBDG_ADMIN_SESSION_SECRET` | A randomly generated secret of at least 32 bytes, distinct from the password | Signs 8-hour, HttpOnly, SameSite=Strict login sessions |
| `LBDG_GITHUB_TOKEN` | A GitHub fine-grained Personal Access Token, **restricted to `lbdgGit/DisclosureHub`** | Saves candidate records to a staging branch and opens draft publication PRs |

Token permissions (fine-grained): **Contents: Read and write; Pull requests: Read and write; Metadata: Read**. Do not grant repository administration, workflows, or organization-wide access. An account with access to the repository and permission to create branches/PRs is required.

Assign variables to Production (and Preview only if you intend to test protected preview builds), then **redeploy**. Never paste these secret values in a chat, issue, PR or repository file.

Also keep **Automatically expose System Environment Variables** enabled in Vercel's Environment Variables settings: publication compares `VERCEL_GIT_COMMIT_SHA` to GitHub `main` and refuses to prepare a release from an out-of-date or preview deployment. [Vercel documents this server-side value](https://vercel.com/docs/environment-variables/system-environment-variables).

## Day-to-day workflow

1. Visit `/admin`, enter the password, and choose the target quarterly edition.
2. Add an event with verified `YYYY-MM` date, source citation and HTTPS URL. Save it initially as **Brouillon**.
3. After documentary review and weight selection, change its status to **Prêt**. Candidate changes are committed only on the GitHub branch `dvi-editor-staging`; they do **not** change the public DVI or CSVs.
4. Preview the exact score and enter/exit list. Check only candidates you intend to publish; the displayed preview reflects that selection. The index status is computed using the **unrounded score**.
5. Once the 36-month reporting period has ended (e.g. January 1, 2027 for the January edition), click **Préparer la Pull Request de publication**. This creates a **draft PR**, including the updated `signals.ts`, DVI configuration and two CSV datasets. It does **not** merge or deploy anything.
6. Review sources, methodology, PR checks and proposed quarterly blog/LinkedIn commentary. Only then merge the PR to deploy the new edition.

The 70 existing public records remain reviewable via the public Signal Board; **editing a published signal from this admin page is not yet implemented**. Such corrections are presently handled via a reviewed PR.

## Security and limitations

- Both the admin page and API require a signed session. State-changing requests also require a matching browser Origin; no admin API uses anonymous write access.
- The login endpoint applies a brief delay after a bad password. For a public internet deployment, also enable **Vercel Firewall/rate limiting** for `/api/admin/login`, use a long random password, and rotate credentials if disclosed.
- `LBDG_GITHUB_TOKEN` exists **only server-side**. All GitHub writes are made by the server; the token is never sent to the browser.
- Candidate staging records are **not on the public website**. However, if the GitHub repository is public, anyone can inspect its branches; **do not add confidential drafts or credentials** to `dvi-editor-staging`.
- A published edition cannot be prepared until the complete 36-month window closes. If the public source file has changed since the editor deployment, publication is blocked and a fresh deployment is required.
- This is a single-editor initial version; there is no multi-user audit-role system, persistent login-attempt database, or background scientific source-verification service. A “Prêt” status remains an editor judgment.

## Validation before first use

- Open `/admin` before setting secrets: it should report unavailable configuration, with no candidate data accessible.
- After setup, test a wrong password, then a correct password. Test a draft save and refresh. Confirm **`readyfordisclosure.com/signals` and both public CSV counts remain unchanged**.
- Verify the GitHub `dvi-editor-staging` branch has the draft commit, and the `/admin` preview reflects it without changing the 6.9 public snapshot.
- In January 2027, create a draft publication PR; verify the DVI score, the 36-month exit list and both CSV exports before any merge.
